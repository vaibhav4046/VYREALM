# Creator workflow audit

Inspected 8 September 2026. Public product documentation is used to understand workflows; no Higgsfield footage, character, music, interface asset or source code was copied. Published feature claims are not an independent quality benchmark.

| Public reference flow | Useful product principle | Existing VYREALM route and remaining boundary |
| --- | --- | --- |
| Cinema Studio: brief, references/cast, shot direction, camera, generation and review | Keep reference selection and shot-level creative controls with the project | Local director, owned keyframe/I2V jobs and retained-shot review exist. Local availability, image quality and identity still need per-job preflight and inspection. [Cinema Studio](https://higgsfield.ai/cinematic-video-generator) |
| Marketing Studio: product inputs and brand direction, recipe/script, generated creative, edit or regenerate | Guide users by the deliverable, while retaining source product assets | Original format recipes, local uploads and FFmpeg product/timeline routes exist. Saving a recipe does not create footage or prove product fidelity. [Marketing Studio guide](https://higgsfield.ai/blog/new-marketing-studio-higgsfield) |
| Voice and avatars: speech generation is separate from mouth animation and dubbing | Expose these as distinct capabilities | Piper narration and Whisper transcription are connected. A MuseTalk checkout is not a qualified lip-sync worker; multilingual dubbing, diarization and avatar generation remain unavailable in the audited production path. [Official audio and lipsync guide](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-lipsync-voiceover-and-aspect-ratios) |

It does not provide a cloud model or free hosted inference. The standalone application must remain usable without an agent client. [MCP product page](https://higgsfield.ai/mcp) |

The immediate missing connection is a unified, saved creator plan that can use uploaded footage without passing through a cinematic neural-generation gate. A podcast edit, tutorial, creator-led product demonstration or social recut already has usable material; it should proceed to source selection, transcript review, trimming, captions and export.

The plan should live inside the existing SQLite project document and revision history. It should contain original workflow identity, a bounded brief, supplied research notes with unverified status, supplied script or clearly disclosed brief outline, shot/asset requirements, speech/caption choices, stage dependencies and actions pointing to existing endpoints. Planning does not write a rendered timeline or mark any source generated.

Six initial entry points cover cinematic work, product ads, talking-head footage, social recuts, tutorials and faceless explainers. Their complete journey is brief → research context → script → shot and asset preparation → narration/captions → edit → inspection → export → local release preparation. Online fact verification, live publishing, neural avatar/lip-sync and automatic highlights must remain explicit missing or unqualified capabilities until connected and tested.

Availability has two independent meanings: an adapter can be implemented while its local runtime is missing or requires preflight. For example, the old capability manifest associates composition with Blender; the actual uploaded-media timeline worker does not need Blender. Several historical MCP limitation strings also lag behind the current keyframe/audio code. The new workflow surface must inspect its actual dependencies rather than repeat those strings.

Acceptance requires an offline uploaded-media plan saved and reopened at the next project revision, unchanged existing timeline/output/history, rejection of foreign asset IDs and stale revisions, and no network/model/render/publication side effects. Renderer success remains governed by the existing worker's media verification and review receipts. A plan or catalogue card is never a completed film.
